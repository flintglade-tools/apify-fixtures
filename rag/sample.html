Deterministic corpus packaging

This Flintglade-controlled fixture demonstrates a small source document for reproducible retrieval-augmented generation corpus packaging. It contains only synthetic instructional prose and is dedicated to the public domain under CC0 1.0.

Provenance requirements

A useful corpus record preserves the source locator, retrieval hash, declared rights basis, extraction method, page boundary, and chunking version. Stable identifiers must exclude timestamps, run identifiers, retry counts, and other observation metadata so unchanged source material produces unchanged records.

  • Fetch only the explicit source selected by the user.
  • Reject unsafe redirects and oversized responses before admission.
  • Keep each chunk linked to its source page and evidence locator.

Deterministic chunking example

Character chunking advances by the configured size minus overlap. A chunk identifier combines the stable page identifier, chunker version, ordinal, and canonical text hash. Exact duplicate pages point to the first admitted page and do not create a second paid corpus unit. Similar but distinct pages remain separate because version one performs exact deduplication only.

step = chunk_size - overlap
chunk_id = sha256(page_id + version + ordinal + text_hash)

Portable manifest fields

FieldPurpose
pageIdStable identity for the extracted page.
canonicalHashDetects exact content changes and duplicates.
rightsBasisRecords the user's explicit declaration and evidence.
chunkIdsLinks every generated child chunk to the paid page.

The resulting manifest is a machine-readable index rather than a legal opinion or factual endorsement. A downstream RAG developer can compare page hashes between package versions, invalidate chunks whose parent page changed, and retain unchanged chunk identifiers without relying on generated summaries or synthetic citations.
